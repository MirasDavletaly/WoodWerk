# WOODWERK — сайт поставщика отделочных панелей

Статический сайт по образцу **lathome.ru**, но со своим брендом, палитрой
и наполнением: прямые поставки стеновых панелей с заводов Китая, розница и опт.

Никаких сборщиков и зависимостей — чистые HTML, CSS и JavaScript.
Чтобы посмотреть, откройте `index.html` в браузере или поднимите локальный сервер
(см. «Как запустить»).

Опционально рядом лежит бэкенд на Go — он принимает заявки с форм и отдаёт
заголовки безопасности, которых статический хостинг не умеет.

## Как запустить

Каталог живёт в базе, поэтому сайт работает вместе с Go-сервером.

**Самый простой способ на Windows** — двойной щелчок по файлу
**`Запустить сайт.bat`** в корне проекта. Он поднимет сервер на порту 8090,
откроет админку в браузере и оставит окно открытым, чтобы было видно журнал
и пароль администратора. Go для этого не нужен: собранная программа
лежит в `server/build/`.

> Порт 8090, а не привычный 8080, выбран намеренно: 8080 почти всегда занят
> Apache из XAMPP, OpenServer или PostgreSQL. Windows разрешает занять такой
> порт дважды, ошибки не будет — но браузеру ответит чужая программа, и вы
> увидите её «404 Not Found». Сервер проверяет это сам: если по его адресу
> отвечает кто-то другой, он пишет об этом в журнал и подсказывает,
> как сменить порт.

Если Go установлен:

```powershell
go run ./server -addr :8090 -dir .
```

### Без запускалки

Двойной щелчок по `server/build/woodwerk-windows-amd64.exe` работает сам по
себе: каталог сайта программа ищет сначала в текущей папке, потом поднимаясь
вверх от собственного файла. Все относительные пути (`data/`, `uploads/`,
`leads.jsonl`) отсчитываются от найденного каталога сайта, а не от места запуска.

Из командной строки, стоя в папке проекта:

```powershell
server/build/woodwerk-windows-amd64.exe
server/build/woodwerk-windows-amd64.exe -addr :8095   # другой порт
```

Отличие от `Запустить сайт.bat` только в двух мелочах: браузер не открывается
сам, и при ошибке окно консоли закроется, если запускать двойным щелчком
из проводника, — но перед закрытием программа ждёт Enter.

При первом запуске сервер сам создаст базу `data/woodwerk.db`, заведёт 10 разделов,
каталог из 59 панелей по прайсу и учётную запись администратора. Логин и **пароль будут
напечатаны в консоли один раз** — сохраните их. Задать свои можно сразу:

```powershell
go run ./server -addr :8090 -dir . -admin-user admin -admin-pass "ваш-пароль"
```

Дальше открыть `http://127.0.0.1:8090/`, админ-панель — `http://127.0.0.1:8090/admin`.

Флаги:

| Флаг | По умолчанию | Зачем |
| --- | --- | --- |
| `-addr` | `:8090` | адрес и порт |
| `-dir` | `.` | каталог с файлами сайта |
| `-db` | `data/woodwerk.db` | файл базы данных |
| `-uploads` | `uploads` | куда складывать фотографии |
| `-max-upload` | `5` | предельный размер фотографии, МБ |
| `-leads` | `leads.jsonl` | файл с заявками |
| `-hsts` | выкл. | слать HSTS — только за настоящим HTTPS |
| `-admin-user` | `admin` | логин администратора |
| `-admin-pass` | — | пароль; на уже созданной учётке **меняет** его |
| `-reset-admin` | выкл. | вернуть пароль к `admin`, если свой забыт |

Логин и пароль можно передать и переменными окружения `ADMIN_USER` / `ADMIN_PASSWORD` —
так они не попадут в историю команд.

## Админ-панель

Адрес — `/admin`. Без входа туда не пускает сам сервер: закрытые страницы
отдают редирект на форму входа, а API отвечает `401`.

| Раздел | Что делает |
| --- | --- |
| Главная | всего изделий, активных, скрытых, категорий, последние добавленные |
| Каталог | таблица с фото, названием, разделом, ценой, статусом и датой; поиск по названию и описанию, фильтры по категории и статусу; кнопки «Редактировать», «Скрыть»/«Показать», «Удалить» |
| Добавить панель | название, описание, цена, раздел, статус, основная фотография, дополнительные фотографии, размер панели, метка на карточке |
| Категории | добавить, переименовать, удалить |
| Настройки | смена логина и пароля |

**Всё, что администратор меняет, сразу видно на сайте** — каталог и страница
изделия читают ту же базу. Скрытое изделие пропадает с сайта, но остаётся
в панели. Удалённое исчезает совсем, вместе со своими фотографиями на диске.

Удаление раздела **не удаляет панели**: изделия остаются, просто без раздела.

### Фотографии

Кнопка «Загрузить фото» открывает выбор файла, картинка показывается сразу
и параллельно уходит на сервер. В базе хранится только адрес вида
`/uploads/2026/08/ab12….jpg`, сами файлы лежат в каталоге `uploads/`.

Принимаются JPG, PNG, WEBP и GIF до 5 МБ (меняется флагом `-max-upload`).
**Тип определяется по содержимому файла**, а не по расширению и не по тому,
что прислал браузер, — переименованный `.exe` не пройдёт.

1. **Контакты — настоящие, из прайса.** Астана, ул. Шугыла 23/2, Коктал №1,
   `+7 (707) 139-49-09` и Алматы, ул. Емцова 9А, 2 этаж, офис №888,
   `+7 (707) 718-20-15`. Заглушками остались почта `info@woodwerk.ru`,
   домен `woodwerk.ru` и реквизиты: в `privacy.html` стоит `БИН 000000000000` —
   подставьте настоящий. Телефон встречается ещё в двух местах `assets/js/main.js`
   (сообщения об ошибке формы и каталога) — если сменится, правьте и там.

   > **Юридические тексты не переписаны.** В `privacy.html` политика и оферта
   > изложены общими словами и не ссылаются на конкретные нормы. Для компании
   > в Казахстане их должен вычитать юрист — выдумывать ссылки на казахстанские
   > законы нельзя.

   > **Способы оплаты.** В подвале стоят нейтральные бейджи «Наличные», «Карта»,
   > «Безналичный расчёт», «Опт по счёту». Замените на то, чем реально принимаете
   > оплату (например Kaspi), — это бизнес-решение, а не вёрстка.
2. **Цены.** Цены панелей в каталоге — из прайса «Вудверк новые 2026», за одну
   панель. А вот условия партнёрской программы в `partnership.html`
   (10/12/15% и пороги в панелях) и строки таблицы получения в `delivery.html` —
   демонстрационные: поставьте свои. Цены панелей правятся в админ-панели,
   всё остальное — прямо в HTML.
3. **Ссылки на соцсети.** В шапке и подвале стоят `href="#"`.
4. **Изображения.** Фотографии панелей в `assets/img/panels/` настоящие — вырезаны
   из прайса, но небольшого разрешения (258–671 px по ширине). Для крупных экранов
   лучше переснять. Остальные SVG в `assets/img/` — сгенерированные текстуры
   и векторные сцены-заглушки: замените фотографиями (те же имена файлов —
   и ничего править в разметке не придётся).
5. **Отзывов на сайте больше нет.** Блок с выдуманными отзывами убран с главной:
   писать вымышленные отзывы нельзя, а настоящих у нас не было. Когда появятся
   реальные — верните секцию по образцу блока «Панели в интерьере».
6. **Отправка форм.** По умолчанию демо-режим: форма проверяется, но никуда
   не уходит. Чтобы включить приём заявок, впишите адрес в `assets/js/config.js`:

   ```js
   window.WOODWERK = { leadEndpoint: "/api/lead" };
   ```

   С бэкендом из `server/` этого делать не нужно — он подставляет адрес сам.
   Клиентские проверки — только удобство для человека. Всё, что важно, дублируйте
   на сервере: см. раздел «Безопасность» ниже.
7. **Карта на `contacts.html`.** Виджет Яндекс.Карт центрирован по приблизительным
   координатам — вставьте свой код встраивания с точной точкой.
8. **Домен в `robots.txt` и `sitemap.xml`** (`https://woodwerk.ru`).

## Настройка внешнего вида

Вся палитра и типографика — в переменных в начале `assets/css/style.css`:

```css
:root {
  --accent: #8c5d30;        /* фирменный акцент, 5.6:1 с белым текстом */
  --accent-on-dark: #d9ab72;/* тот же акцент на тёмных секциях */
  --nav: #b39a7c;           /* бежевая полоса меню */
  --ink: #1a1512;           /* основной тёмный */
  --bg: #faf7f2;            /* тёплый фон */
  --black: #0f0d0b;         /* секция «Панели по акции» */
  --container: 1320px;      /* ширина контента */
}
```

Изменение `--accent` перекрашивает кнопки, ссылки, иконки и акценты по всему сайту.
Если меняете цвета — проверьте контраст: белый текст на кнопке должен давать
не меньше 4.5:1, иначе кнопка перестанет проходить по доступности.

## Товары в каталоге

Статических карточек в `catalog.html` больше нет — каталог рисуется скриптом
по ответу `GET /api/products`, а фильтр по категориям строится из тех разделов,
где реально что-то есть. Чтобы добавить или изменить изделие, откройте админ-панель;
править HTML руками не нужно.

Адреса вида `catalog.html?cat=wood` продолжают работать: слаг раздела
подставляет соответствующий чекбокс фильтра. Второй фильтр — размер панели,
адрес `catalog.html?size=3000x1220`.

### Откуда взялось наполнение

Каталог из поставки (`server/seed.go`) собран по прайсу «Вудверк новые 2026»:
59 панелей, 10 разделов, цены в тенге за одну панель. Фотографии вырезаны
из того же прайса и лежат в `assets/img/panels/` — имя файла совпадает
с артикулом (`lfi-1012.jpg`, `nb-nb-003-1.jpg`).

Разделы каталога: `sale`, `wood`, `fabric`, `stone`, `matte`, `leather`,
`plaster`, `metal`, `slats`, `budget`.

Размеры панели (колонка `size`, белый список в `server/api_admin.go`):

| Значение | Что показывается | Позиций |
| --- | --- | --- |
| `2800x1220` | 2800×1220×5 мм | 2 |
| `3000x1220` | 3000×1220×5 мм | 42 |
| `3000x1200` | 3000×1200×5 мм | 15 |

Раньше в этой колонке жила порода дерева и называлась она `wood`. На базах,
созданных прошлыми версиями, `migrate()` переименовывает колонку на месте —
данные и содержимое сохраняются, но старые значения (`oak`, `ash` и прочие)
перестают совпадать с белым списком и в фильтр не попадают.

### API

| Метод и адрес | Что отдаёт |
| --- | --- |
| `GET /api/products` | активные изделия; параметры `category`, `size`, `search`, `sort`, `lang` |
| `GET /api/products/{id}` | одно изделие с дополнительными фотографиями; параметр `lang` |
| `GET /api/categories` | разделы каталога с числом изделий; параметр `lang` |

Скрытые изделия наружу не отдаются **никогда** — ни списком, ни по прямой ссылке.

### Таблицы

```
categories      id, name, name_kk, name_en, slug, sort_order, created_at
products        id, title, title_kk, title_en,
                description, description_kk, description_en,
                price, image_url, category_id, status,
                size, badge, search_text, created_at, updated_at
product_images  id, product_id, image_url, sort_order, created_at
admin_users     id, username, password_hash, created_at, updated_at
sessions        token_hash, user_id, csrf, created_at, expires_at
```

`search_text` — название и описание в нижнем регистре. Отдельное поле нужно
потому, что `LOWER()` в SQLite умеет приводить регистр только у латиницы,
и без этого поиск по русским словам не находил бы ничего.

## Три языка

В верхней строке сайта — переключатель **Рус / Қаз / Eng**. На планшетах
и телефонах верхняя строка скрыта, поэтому там он живёт в выпадающем меню.

Как выбирается язык при заходе: параметр `?lang=kk` в адресе, затем прошлый
выбор посетителя, затем язык браузера, и только потом русский. Выбор
запоминается в браузере и держится при переходах между страницами.

### Что переведено

| Слой | Где хранится перевод |
| --- | --- |
| Тексты страниц, меню, формы, подписи, мета-описания | `assets/i18n/kk.json`, `assets/i18n/en.json` |
| Названия и описания панелей | колонки `title_kk`, `title_en`, `description_kk`, `description_en` в таблице `products` |
| Названия категорий | колонки `name_kk`, `name_en` в таблице `categories` |

Переводы каталога **необязательны**: где перевода нет, сайт покажет русский
текст. Заполняются они в админ-панели — в форме изделия есть раздел
«Переводы», у категорий два дополнительных поля.

### Как это устроено

Русский — исходный язык, он лежит прямо в разметке. Переводимые места
помечены атрибутом `data-i18n` (и `data-i18n-placeholder`, `data-i18n-title`
и подобными для атрибутов), значение — ключ в словаре. Скрипт
`assets/js/i18n.js` запоминает исходный русский текст, подменяет его
переводом и возвращает обратно при выборе «Рус» — второй словарь для
русского не нужен.

Переводится не отдельное слово, а блок целиком, вместе с внутренними
`<b>`, `<a>` и `<br>`: порядок слов в казахском и английском другой,
и разбитая на куски фраза собралась бы криво.

Каталог при смене языка перезапрашивается у сервера с параметром `lang`,
потому что названия панелей живут в базе, а не в словаре.

### Как добавить или поправить перевод

Ключи — это хеш от русского текста, поэтому вручную их писать не нужно:

1. Правите русский текст в HTML.
2. Открываете `assets/i18n/ru.json` и находите новый ключ по тексту.
3. Дописываете строку с тем же ключом в `kk.json` и `en.json`.

Если перевода для ключа нет, сайт молча покажет русский — пустых мест
не появится. Словари отдаются без кэширования, так что правка видна сразу
после перезагрузки страницы.

> **Казахский перевод машинный, вычитки носителем не было.** Для витрины
> он годится, но перед серьёзным запуском текст стоит показать человеку,
> для которого казахский родной, — особенно названия пород дерева
> и юридические формулировки.

всегда с проверкой, словари переводов — тоже с проверкой, иначе правка
перевода не дошла бы до посетителя.

### Лишние слои

`will-change: opacity, transform` стоял на правиле `.reveal` и не снимался
никогда. На главной это 75 элементов, из которых 74 давно показаны и больше
не анимируются, — браузер держал под них отдельные слои впустую.

Подсказка убрана совсем: прозрачность и сдвиг браузер и так отдаёт
композитору, а `will-change` — точечная подсказка для заведомо тяжёлой
анимации, а не значение по умолчанию.

Подчёркивание в мегаменю росло через `width` — свойство, которое
пересчитывает макет на каждом кадре. Заменено на `transform: scaleX()`,
тот же приём, что уже использовался у полоски на карточке категории.

## Телефон

### Касание — это не наведение

Главная причина «дёрганья» карточек была в том, что на сенсорном экране
касание включает `:hover`: карточка подпрыгивала и **оставалась** в этом
состоянии, пока не тронешь другое место. В стилях было 17 правил наведения
с движением и ни одной защиты.

Теперь все такие эффекты выключены через `@media (hover: none)`. Проверяется
возможность ввода, а не ширина экрана: у планшета в альбомной ориентации
экран широкий, а палец тот же.

### Ленты вместо стены

Акционные панели и разделы на телефоне листаются вбок. Следующая карточка
выглядывает из-за края: сразу видно, что можно листать.

Ленты крутятся **только вбок**. Это пришлось задать явно: при
`overflow-x: auto` спецификация CSS делает вторую ось тоже прокручиваемой,
и внутри набегало 20–22 пикселя запаса от анимации появления карточек.
Палец, которым хотели пролистать страницу вниз, сначала утаскивал ленту —
казалось, что товары ездят сами по себе. Лечится `overflow-y: hidden`
и отменой въезда карточек снизу.

`touch-action: pan-x` для этого **не подходит**: он запрещает вертикальный
жест целиком, и страница перестаёт листаться пальцем поверх ленты.
Проверено настоящими жестами — вертикальный свайп по ленте листает
страницу, горизонтальный листает ленту, диагональный не сдвигает её вниз.

У лент ещё `overscroll-behavior-x: contain` — палец, доехавший до края,
не тянет за собой страницу и не срабатывает как жест «назад» в браузере.

### Значок меню

Полоски были прижаты к верхнему краю кнопки: у элемента стояло
`place-items: center` — свойство grid, которое для flex по главной оси
ничего не делает. Заменено на `align-items` + `justify-content`.

### Админ-панель с телефона

Работают **все** функции, что и с компьютера: вход, добавление панелей
с загрузкой фотографии, скрытие, удаление, категории, смена пароля и логина.

| Было | Стало |
| --- | --- |
| таблица шириной 916px на экране 390 | строки показаны карточками, ничего не уезжает |
| 47 целей мельче 40px | кнопки 46px, мелких целей не осталось |
| до кнопок надо листать вбок | действия крупным рядом под карточкой |

Подписи полей в карточках берутся из `data-label`: шапки таблицы на телефоне
нет, и «22.08.2026» без подписи ни о чём не говорит.

> **Безопасность та же.** Отдельной мобильной версии нет — это одно и то же
> приложение, менялась только раскладка. Проверка входа, прав и CSRF живёт
> на сервере и от ширины экрана не зависит. Проверено с телефона: закрытая
> страница уводит на форму входа, API без сессии отвечает `401`.

## Доступность и живучесть

Раздел появился после сплошной проверки замерами: контраст считали по
настоящим пикселям страницы, размеры целей — по рамкам элементов в браузере,
а не на глаз.

### Страница не исчезает, если скрипты не сработали

Блоки на сайте появляются при прокрутке, и до этого они были прозрачными:
`.reveal { opacity: 0 }`. Правило действовало безусловно, поэтому любая
осечка в JS — заблокированный расширением файл, ошибка в старом браузере,
обрыв на медленной сети — оставляла от главной пустой экран. Скрыто было
75 блоков из 75.

Теперь прятать содержимое разрешено только под классом `js`, который ставит
`assets/js/boot.js` в `<head>`. Нет скрипта — нет класса — страница видна
целиком. Отдельным файлом, а не строкой в разметке: политика безопасности
разрешает только собственные скрипты, встроенный `<script>` браузер бы не
выполнил.

Проверяется тремя способами: со скриптами, выключенными в браузере;
с заблокированным `boot.js` при работающих остальных; и обычной загрузкой,
где появление должно работать по-прежнему.

### Контраст

Считали по формуле WCAG, фон брали из пикселей отрисованной страницы —
обход разметки врёт там, где под текстом фотография.

| Что | Было | Стало |

| Пункты меню на бежевой полосе | 2,68:1 | 6,75:1 |
| Пункт «Каталог» | 4,27:1 | 4,72:1 |

Полосу меню не перекрашивали: бежевый `#b39a7c` остался тем же, тёмным стал

### Клавиатура и читалки

- Ссылка «Перейти к содержимому» первым элементом на каждой странице:
  раньше до таблицы или каталога нужно было пройти Tab всю шапку и меню.
  Видна только когда на ней фокус.
- Иерархия заголовков без пропусков. Было `h1 → h4` на главной и в контактах,
  `h1 → h3` в каталоге и карте сайта: для читалки это два пропущенных раздела.
  Блокам без видимого заголовка добавлен заголовок для читалок (`.u-sr`).
- Цели нажатия не мельче 24×24 по WCAG 2.2: крошки были 20px, телефон и почта
  в контактах — 22px. Переключатель языка на телефоне поднят с 35 до 44px.

### Уменьшенное движение

При `prefers-reduced-motion` анимации выключены, но переходы идут 80мс,
а не мгновенно: полностью мгновенная смена состояния лишает кнопки и поля
отклика на нажатие. Блоки при этом показываются сразу, без въезда.

## Раскрывающиеся блоки без магических чисел

Подменю, ответы на вопросы и панель фильтров раскрывались через
`max-height` с числом, взятым на глаз: 760px, 460px, 1400px. Пока
содержимое короче — работает.

Панель фильтров строится по категориям из базы, а категории добавляет
владелец из админки. Замерено: панели уже нужно 1163px из 1400px — запас
в шесть строк. Седьмая добавленная категория обрезалась бы молча.

`grid-template-rows: 0fr → 1fr` раскрывает ровно на высоту содержимого,
сколько бы его ни было. Проверено добавлением сорока категорий: панель
выросла до 2924px и показала последнюю.

Вертикальные отступы внутри пришлось увести в ту же анимацию: `padding`
несжимаем, и без этого закрытый блок оставался высотой 18 и 28 пикселей
вместо нуля. Да, `padding` — макетное свойство, и кадры при раскрытии
стоят пересчёта. Для блока, который человек открывает вручную раз в сессию,
это дешевле, чем молча обрезанный список.

## Страница 404

Раньше на неверный адрес отвечала строчка `404 page not found` шрифтом
браузера на белом фоне — без меню, без дороги назад. Теперь это страница

разметки `sitemap.html`, чтобы шапка и подвал не разошлись с остальными
страницами при следующей правке меню. Поисковикам закрыта `noindex`.

Заодно у всех страниц появились адреса без `.html`. Раньше красивый адрес
был только у каталога и карточки изделия: `/catalog` работал, а `/about`
отдавал 404 — при том что ссылка из письма или с визитки чаще выглядит
именно так.

## Кнопка звонка в шапке телефона

## Редизайн: что поменялось

Первая версия была самостоятельной по визуалу. Во второй сайт подведён ближе
к референсу lathome.ru и переработан адаптив.

**Шапка.** Вместо одной тёмной панели теперь три уровня, как у референса:
светло-бежевая строка с графиком и адресом, белая строка с логотипом,
соцсетями и телефоном, и отдельная бежевая полоса меню (`--nav`), в которой
«Каталог» выделен тёмным. При прокрутке прилипает только полоса меню — верхние
две уезжают, чтобы не съедать высоту на ноутбуке.

**Главный экран.** Текст и кнопки по центру, а не по левому краю. Заголовок
стал обычным предложением вместо капса, кнопки — белая заливка плюс контурная.
Затемнение фона ослаблено, вместо него тень под текстом: текстура дерева теперь
читается, а контраст сохраняется.

**Акция.** Секция переехала на чёрный фон. Артикул панели — по центру
вверху карточки, цена и «Смотреть раздел →» — внизу. За карточками идёт
гигантская полупрозрачная надпись, как в референсе.

**Надзаголовки убраны.** Над каждым заголовком раньше стояла подпись-ярлык
(«О компании», «Материалы»). Это лишний слой: заголовок должен
работать сам. Все 19 штук удалены, а заголовки переписаны так, чтобы не терять
смысл: «Коротко о главном» стало «Частые вопросы», «Три способа рассчитаться» —
«Оплата: три способа рассчитаться» и так далее.

**Контраст приведён к AA.** Старые `--muted` (3.6:1) и `--accent` (3.7:1)
не дотягивали до нормы 4.5:1 — белый текст на кнопках давал всего 3.99:1.
Сейчас `--muted: #6f6259` (5.5:1) и `--accent: #8c5d30` (5.6:1 с белым).
На тёмных фонах используется отдельный `--accent-on-dark: #d9ab72` (9.2:1).

**Мелочи, которые заметны не сразу.** Кольцо фокуса с клавиатуры, свои
полосы прокрутки, цвет каретки, табличные цифры в ценах и телефонах,
`text-wrap: balance` для заголовков, отступ подчёркивания у ссылок.

## Адаптив

Точки перелома выбраны там, где ломается макет, а не по списку устройств.

| Ширина | Что происходит |
|---|---|
| до 1440px | Контейнер 1180px, мегаменю плотнее — иначе на 1366px поля почти нулевые |
| до 1280px | Контейнер во всю ширину, пункты меню компактнее |
| до 1180px | Прячутся второстепенные пункты меню и промо-блок в мегаменю |
| до 1024px | Полоса меню уходит в бургер, шапка становится липкой, сетки в 2 колонки |
| до 720px | Одна колонка, нижняя панель действий, акционные панели — карусель |
| низкий экран | При высоте окна до 820px герой и отступы секций ужимаются |
| `hover: none` | Ничего не прячется за наведением, hover-трансформации отключены |

Что сделано именно для телефона:

- **Нижняя панель действий** — «Позвонить» и «Оставить заявку» всегда под рукой.
- **Акционные панели — карусель** со свайпом: шесть карточек по 400px превращались
  в 2500px вертикальной прокрутки.
- **Фильтры каталога свёрнуты** в кнопку со счётчиком выбранного. Раньше до
  первого товара надо было пролистать 15 чекбоксов.
- **Тач-цели от 44px**, текст от 16px.

Проверялось не на глаз: страница снималась в настоящей мобильной эмуляции
через CDP, замерялись `scrollWidth` против ширины экрана и размеры всех
интерактивных элементов. Нашлось и исправлено горизонтальное переполнение
(телефон в шапке растягивал страницу до 451px при экране 390px) и 14 тач-целей
меньше 40px.

## Бэкенд на Go

Стандартная библиотека плюс одна зависимость — `modernc.org/sqlite`, драйвер
SQLite на чистом Go. **Без cgo**: собирается и работает на любом сервере,
ставить SQLite отдельно не нужно, вся база — один файл.

Что делает сервер:

- отдаёт статику и **заголовки безопасности**, которые нельзя выставить метатегом:
  HSTS (флаг `-hsts`, только за реальным HTTPS), `X-Frame-Options: DENY`,
  `frame-ancestors 'none'`, `Permissions-Policy`, `nosniff`, COOP;
- закрывает доступ к точечным файлам, к `.md`, `.py`, `.go`, `.db`, `.jsonl`
  и к каталогам `server/` и `data/`;
- держит каталог панелей в SQLite и отдаёт его сайту через `/api/…`;
- поднимает админ-панель с авторизацией, загрузкой фотографий и правами;
- принимает заявки на **`POST /api/lead`**: проверяет honeypot, имя, 11 цифр
  телефона, длину комментария, режет тело до 16 КБ, ограничивает 5 заявками
  за 10 минут с одного адреса и дописывает результат в `leads.jsonl`;
- на honeypot отвечает «успехом», чтобы бот не понял, что его отсеяли;
- корректно завершается по Ctrl+C.

Фронтенд узнаёт адреса из `assets/js/config.js`. Go-сервер подменяет этот файл
на лету, поэтому при запуске через него править ничего не нужно.

### Тесты

```powershell
go test ./server
go vet ./server
```

Тесты поднимают временную базу и проверяют поиск по-русски, хеширование пароля,
сокрытие изделий от публичного API, каскады при удалении и разбор адресов файлов.

**Пошаговая инструкция — в отдельном файле [DEPLOY.md](DEPLOY.md).**
Там всё от чистого Ubuntu до работающего HTTPS, плюс резервные копии
и что делать, когда не работает. В папке `deploy/` лежат готовые файлы:

| Файл | Что это |
| --- | --- |
| `deploy/install.sh` | ставит сайт, службу и права одной командой |
| `deploy/woodwerk.service` | служба systemd с ограничением прав |
| `deploy/nginx.conf` | конфиг nginx с HTTPS и лимитом попыток входа |
| `deploy/backup.sh` | резервные копии базы, фотографий и заявок |

Дальше — подробности для тех, кто хочет собрать сам.

Нужен **Go 1.25 или новее** — этого требует драйвер SQLite. Если на сервере
версия старше, есть два пути: поставить свежий Go с go.dev или собрать бинарник
на другой машине и просто скопировать — зависимостей во время работы у него нет.

```bash
# сборка под сервер (можно делать на своей машине)
GOOS=linux GOARCH=amd64 go build -trimpath -ldflags="-s -w" \
    -o server/build/woodwerk-linux-amd64 ./server
```

Дальше на сервере:

```bash
# 1. файлы сайта, например в /var/www/woodwerk
# 2. запуск
ADMIN_USER=admin ADMIN_PASSWORD='надёжный-пароль' \
  ./woodwerk-linux-amd64 -addr 127.0.0.1:8080 -dir /var/www/woodwerk -hsts
```

Сервис systemd (`/etc/systemd/system/woodwerk.service`):

```ini
[Unit]
Description=WOODWERK
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/woodwerk
Environment=ADMIN_USER=admin
Environment=ADMIN_PASSWORD=надёжный-пароль
ExecStart=/var/www/woodwerk/woodwerk-linux-amd64 -addr 127.0.0.1:8080 -dir /var/www/woodwerk -hsts
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

Впереди — nginx с сертификатом, который проксирует на `127.0.0.1:8080`:

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 20m;   # иначе большие фотографии не пройдут
}
```

Флаг `-hsts` включайте только когда HTTPS уже работает.

**Что забирать в резервную копию:** `data/woodwerk.db`, каталог `uploads/`
и `leads.jsonl`. База — обычный файл, копируется как есть.

**Права:** каталоги `data/` и `uploads/` должны быть доступны на запись
пользователю, от которого работает сервис.

## Безопасность

Сайт статический, поэтому основные риски — это внедрение чужого кода на странице,
спам через формы и утечка данных при переходах наружу. Что сделано:

**Content Security Policy.** В `<head>` каждой страницы прописан строгий CSP:
скрипты — только свои (`script-src 'self'`), стили — свои плюс Google Fonts,
картинки — свои и `data:`, фреймы — только Яндекс.Карты, отправка форм — только
на свой домен. `'unsafe-inline'` не используется: ради этого все inline-стили
вынесены в классы-утилиты (раздел 22 в `style.css`). Любой посторонний скрипт,
попавший в разметку, просто не выполнится.

**Заголовки сервера.** `_headers` (Netlify, Cloudflare Pages, Vercel) и `.htaccess`
(Apache; внутри — готовый блок для nginx) добавляют то, чего нельзя выставить
метатегом: HSTS, `X-Frame-Options: DENY`, `frame-ancestors 'none'` от кликджекинга,
`Permissions-Policy` (камера, микрофон, геолокация выключены), `nosniff`,
`Cross-Origin-Opener-Policy`, скрытие версии сервера и запрет листинга каталогов.

> На GitHub Pages свои заголовки задать нельзя — там работает только CSP из метатега.

**Админ-панель.** Пароль **нигде не хранится в открытом виде** и не попадает во
фронтенд: в базе лежит PBKDF2-HMAC-SHA256, 210 000 итераций, со своей случайной
солью у каждой учётной записи. Сравнение — за постоянное время, чтобы по задержке
ответа нельзя было подобрать пароль по символам.

Сессия — 32 случайных байта в cookie `HttpOnly` (скрипту недоступна), `SameSite=Lax`,
`Secure` за HTTPS, живёт 12 часов. В базе хранится не сам токен, а его SHA-256:
даже с доступом к файлу базы войти под чужой сессией не выйдет.

Изменяющие запросы (`POST`, `PUT`, `PATCH`, `DELETE`) дополнительно требуют
заголовок `X-CSRF-Token`, который умеет подставить только наш скрипт.

Форма входа ограничена 10 попытками с адреса за 15 минут. Ответ при неверном
логине и при неверном пароле одинаковый, и хеш считается даже для несуществующего
логина — чтобы по времени ответа нельзя было выяснить, какие логины существуют.

Закрытые страницы `/admin/...` проверяются **на сервере**: без сессии посетитель
получает редирект на форму входа, а API — `401`. Смена пароля закрывает все
остальные сеансы.

Всё, что приходит из формы, проверяется на сервере заново: длина названия,
диапазон цены, существование раздела, допустимость статуса и размера. Адрес
фотографии обязан быть путём внутри сайта — ни `javascript:`, ни чужой домен,
ни `..` в базу не попадут. Загруженный файл определяется по содержимому,
а не по расширению.

Разметка в админке собирается через DOM API, а не подстановкой строк в `innerHTML`,
поэтому название изделия не может превратиться в исполняемый HTML.
> Полный набор даёт Netlify, Cloudflare Pages или бэкенд из `server/`.

**Формы.** Проверки продублированы на клиенте и в Go-бэкенде. На клиенте:
honeypot-поле `company`, скрытое от людей; отсечка отправок быстрее
1,5 секунды после загрузки; не больше 5 отправок за 10 минут с вкладки;
ограничения `maxlength` на всех полях; вырезание управляющих символов;
защита от загрязнения прототипа (`__proto__`, `constructor`, `prototype`
в payload не попадают).

**JavaScript.** Нигде не используется `innerHTML` — только `textContent`, поэтому
XSS через данные невозможен. Параметры из адресной строки (`?cat=`, `?wood=`)
не подставляются в CSS-селектор, а сравниваются со списком существующих
фильтров — иначе это была бы инъекция в `querySelector`.

**Ссылки и фреймы.** Всем внешним ссылкам проставляется `rel="noopener noreferrer"`
(в разметке и дополнительно из JS), у iframe Яндекс.Карт стоит `sandbox`
и `referrerpolicy`. Метатег `referrer` ограничивает передачу адреса
до `strict-origin-when-cross-origin`.

**Куда сообщать об уязвимостях.** `.well-known/security.txt` по RFC 9116.

### Проверка безопасности

Провёл разбор всего кода, не только последних правок. Нашлось и закрыто:

| Что | Чем грозило |
| --- | --- |
| **Удаление файлов вне каталога загрузок.** Путь делился только по `/`, а Windows считает разделителем и `\`. Запрос `POST /api/admin/upload/delete` с адресом `/uploads/a\..\..\file` доставал файл снаружи | стирание любого файла, до которого дотягивается служба |
| **Служебные файлы отдавались наружу.** `/deploy/nginx.conf`, `/deploy/install.sh`, `/deploy/woodwerk.service` открывались по прямой ссылке | пути на сервере, устройство службы и её права — подсказка для взлома |
| **Лимит попыток входа за прокси был общим.** За nginx все посетители выглядят как `127.0.0.1`, и десять неудач от кого угодно закрывали вход всем | владелец не мог войти, пока чужой перебор не выдохнется |
| **Свой пароль попадал в журнал.** `-admin-pass` печатался в открытом виде | `journalctl` читают не только владельцы |
| **Кука сессии без флага `Secure` за прокси.** `r.TLS` за nginx пустой, признак HTTPS приходит заголовком | перехват сессии в открытой сети |

На каждую находку есть тест, который её воспроизводил до исправления:
`server/security_test.go` и `server/upload_security_test.go`.

Заголовкам `X-Real-IP` и `X-Forwarded-Proto` сервер верит **только** когда
соединение пришло с петлевого адреса, то есть от своего же nginx. Заголовок
от постороннего игнорируется — иначе лимит обходился бы подстановкой
любого адреса в каждом запросе.

### Чего клиентский код не может — сделайте на сервере

Всё перечисленное выше обходится через консоль браузера. Когда подключите
реальный приём заявок, обязательно продублируйте на бэкенде:

- валидацию имени, телефона и длины комментария;
- CSRF-токен (в `main.js` уже показано, куда его класть) и `SameSite=Strict` для cookie;
- ограничение частоты запросов по IP;
- защиту от спама вроде reCAPTCHA или Cloudflare Turnstile;
- параметризованные запросы к БД и экранирование при выводе заявок в админку;
- HTTPS с актуальным сертификатом.
